# 内容包机制与生物泡沫

本文件对应两项实现：内容包开关框架，以及“医疗 - 生物泡沫”内容包。

---

## 1. 内容包框架

### 1.1 清单

| id | 中文名 | 内容 | 关闭后受影响的 Def |
|---|---|---|---|
| `weapons_mechanoid_launchers` | 武器 - 机械族回收发射器 | 五把发射器 | 5 个武器 ThingDef + 5 个弹头 ThingDef + 5 个 AmmoSetDef |
| `medical_biofoam` | 医疗 - 生物泡沫 | 生物泡沫注射器 | 1 个 ThingDef + 1 个 JobDef（+ 自动生成的制作配方） |

注册位置：`source/LatiosArsenal/ContentPacks.cs`。
Def 位置：`1.7/Defs/LatiosArsenal/Packs/<内容包>/`。

### 1.2 关闭时如何做到“不加载”

1. `1.7/Patches/LatiosArsenal_ContentPacks.xml` 里每个内容包若干条 `LatiosArsenal.PatchOperationContentPack`；
2. 该操作在 `LoadedModManager.ApplyPatches` 阶段（Def 实例化之前）运行
   （`Source/Verse/LoadedModManager.cs`：`CreateModClasses` → `LoadModXML` → `ApplyPatches` → `ParseAndProcessXML`）；
3. 内容包启用 → 空操作；关闭 → 按 `xpath` 删除节点，并把被删的 `defName` 记入 `ContentPackTranslationCleanup`；
4. 随后 `LoadedLanguage.InjectIntoData_BeforeImpliedDefs` 的前置补丁剔除这些 Def 的翻译键，
   避免“找不到对应 Def”的翻译错误（日志里会显示剔除条数）。

因此关闭的内容包不进入 `DefDatabase`，也不生成配方、不占贴图/翻译注入。

### 1.3 设置与存档

| 关注点 | 实现 |
|---|---|
| 设置存储 | `LatiosSettings`（`ModSettings`），只存 `disabledPacks` 列表；新增内容包默认开启 |
| 读取失败 | `IsPackEnabled` 抛错或读不到时按“启用”处理（fail-open） |
| 设置界面 | `选项 → 模组设置 → Latios' Arsenal（内容包）`，逐包勾选 + 当前状态（已加载 / 本次未加载 / 已改动-需重启） |
| 生效时机 | 下次启动游戏（Def 载入前决定） |
| 存档中途调整 | `GameComponent_LatiosArsenalPacks` 在存档写入启用快照；载入时比对，差异写日志 + 消息栏提示 |
| 性能 | 判定只在启动期做一次；运行期只保留只读集合 `DisabledAtLoad`，无逐帧逻辑 |

### 1.4 新增内容包的步骤

1. `1.7/Defs/LatiosArsenal/Packs/<新包>/` 放 Def；
2. `ContentPacks.cs` 的 `All` 里登记 id + 两条 Keyed 键；
3. `1.7/Patches/LatiosArsenal_ContentPacks.xml` 追加 `PatchOperationContentPack`（一条 Operation 一条 XPath）；
4. 三种语言的 `Keyed/LatiosArsenal.xml` 补名称与描述。

## 2. 生物泡沫注射器

Def：`1.7/Defs/LatiosArsenal/Packs/Medical_BioFoam/Apparel_BiofoamInjector.xml`
JobDef / 作业：`1.7/Defs/LatiosArsenal/Packs/Medical_BioFoam/JobDefs_BioFoam.xml`、`source/LatiosArsenal/JobDriver_ReloadBiofoamInjector.cs`
Comp：`source/LatiosArsenal/CompBiofoamInjector.cs`
占位贴图：`1.7/Textures/Things/Pawn/Humanlike/Apparel/Latios/BiofoamInjector.png`

### 2.1 行为

| 项目 | 值 | 可调位置 |
|---|---|---|
| 槽位 | 腰带（`bodyPartGroups = Waist`，`layers = Belt`） | Def `apparel` |
| 触发阈值 | `BleedRateTotal > 1.0`（流血速度 100%） | `bleedThreshold` |
| 触发效果 | 对流血最快的伤口做一次包扎，质量固定 **75%**，立刻停住该处流血 | `tendQuality`、`FindWorstBleedingInjury` |
| 最大充能 | **4** | `maxCharges` |
| 每次触发消耗 | 1 次充能 | — |
| 每份医药 | +2 充能 | `chargesPerMedicine` |
| 装填方式 | **Job**：走到医药处（随身携带则原地）→ 装填耗时 → 消耗 1 份医药 | `reloadWorkTicks`（默认 240 tick ≈ 4 s） |
| 装填触发 | 装备上的「补充生物泡沫（x/4）」按钮；医药找不到时按钮禁用 | `CompGetWornGizmosExtra` |
| 兜底检查间隔 | 60 tick（1 秒） | `fallbackCheckInterval` |
| 制作 | 机械加工台，研究「医药生产」，工艺 5；25 钢铁 + 2 工业医药 + 2 零部件，工作 9000 | Def `recipeMaker` / `costList` / `statBases` |
| 重量/血量/装备耗时 | 1.2 kg / 80 HP / 1.5 s | `statBases` |

### 2.2 装填 Job 的流程

```
按钮 → CompBiofoamInjector.StartReloadJob()
        ├─ 先在背包里找医药；没有就用 GenClosest 找地图上最近、可达、未禁用的医药
        └─ JobMaker.MakeJob(Latios_ReloadBiofoamInjector, 医药, 腰带装备)
JobDriver_ReloadBiofoamInjector.MakeNewToils()
        ├─ 医药不在背包 → Toils_Goto.GotoThing(ClosestTouch)
        ├─ Toils_General.Wait(reloadWorkTicks) + 进度条
        └─ Toils_General.Do → CompBiofoamInjector.FinishReload(医药)
                ├─ 消耗 1 份医药（可堆叠则 SplitOff 后销毁）
                └─ AddCharges(chargesPerMedicine)
```

失败条件：装备被脱下、充能已满、医药被销毁/被禁用。
随身携带医药时同样要经过 `Wait`，只是省掉走路。

### 2.3 性能设计

- **事件驱动**：Harmony postfix 挂在 `Pawn.PostApplyDamage`（`Source/Verse/Pawn.cs:3185`），只在受伤那一下检查；
- **低频兜底**：`CompTick` 每 60 tick 一次，覆盖非伤害来源的流血、读档、hediff 注入；
- **便宜的判定**：先 `charges → wearer → CanBleed` 判空，再读 `HediffSet.BleedRateTotal`
  （`HediffSet.cs:25` 的缓存字段，仅 hediff 变化时 `DirtyCache`），只有超过阈值才遍历 `hediffs`；
- 医药查找只在点击按钮时执行（`GenClosest` + `CanReserve`），不进逐帧路径；
- 空闲时每个穿戴者每秒：1 次整数取模 + 1 次 float 比较。

### 2.4 已知限制 / 后续部分

- 贴图为占位图，仅标注 `BIOFOAM`。
- 只做“止血 + 75% 包扎质量”，没有感染处理、疼痛缓解、创伤修复等后续效果。
- 装填要求场上存在医药；没有任何医药时按钮禁用，不做“先去买药”的跨图逻辑。
- 未做充能消耗的可视化（只有消息与检视面板文字）。
